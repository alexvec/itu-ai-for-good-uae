# What the official template asks for

Source: `sources/submission-template.docx`, the AI for Good Sandbox Hackathon template. The sample inside it is a smart-pen education story. That sample is not this entry. The structure is.

The report maps every ITU-T Y.3172 node to three columns: the use case, one AI Readiness dimension, and one policy document.

Nodes in the template, in order: SRC, C, PP, M, P, D, SINK.

The template's own note says the Readiness mapping is not limited to data and model handling. It also asks for strategy alignment, interface design, and collaboration between AI and a human.

The error scenario is a numbered sequence. It has to include a step where the deployment is popular, then a step where the deployment causes a controversy, then a step where the knowledge base is what decides the action. The template says the corrective action has to follow pre-agreed rules. Its example of a judge-added twist is an escalation from a consumer issue to a data-privacy breach, where the knowledge base prohibits a use, requires consent and purpose limitation, and refers the case to an oversight body.

Required report sections, from the event FAQ, in this order:

1. Short introduction of the agent.
2. Description of the use case.
3. Requirements of the use case.
4. Mapping to ITU-T Y.3172.
5. Mapping to the ITU AI Readiness Report 2.0.
6. Requirements mapping to local policies.
7. Evaluation scenario covering the technical solution and the policy.
8. Policy and standards gaps found by that mapping.

The event FAQ says accuracy of the prototype is not an evaluation criterion.
